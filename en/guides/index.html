SVN guides

Practical setup and workflow guides for StoneSVN, an MIT-licensed Subversion desktop client. Start with your operating system, then choose the task you want to complete.

Install and open a working copy

StoneSVN requires a separately installed SVN CLI. These guides explain the available packages, executable discovery and opening an existing working copy.

  • An open-source SVN client for macOS, Windows and Linux

    Use StoneSVN to review SVN working copies, select files to commit and stash text changes. Installation requirements and current limits explained.

  • An SVN GUI for Linux: install StoneSVN and connect your working copy

    Choose the Linux x86_64 AppImage, DEB or RPM, install the separate SVN CLI, and use StoneSVN to review diffs and select changes to commit.

  • An open-source SVN client for Windows: install StoneSVN and the SVN CLI

    Choose the StoneSVN x64 EXE or MSI, install an SVN command-line client, locate svn.exe and open an existing Subversion working copy on Windows.

Review and organize local changes

Understand which settings stay local to StoneSVN and which changes become part of SVN history.

  • Ignore logs and generated files across SVN working copies

    Configure StoneSVN global file filters with examples for logs, .DS_Store and node_modules, and understand how they differ from SVN ignore properties.

  • Stash selected SVN text changes with StoneSVN

    Save part of an unfinished SVN text change locally, keep other edits in your working copy, and restore the stash when you resume the task.

Version context and sources

These are project-authored guides checked against StoneSVN v1.1.2. Each article links to source or supporting documentation and explains relevant limits. General Merge, Switch and line-by-line Blame interfaces are not currently available.
