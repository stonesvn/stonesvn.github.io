Stash selected SVN text changes with StoneSVN

Project documentation · Checked against StoneSVN v1.1.2 · 18 October 2026

StoneSVN can stash selected text hunks from a working copy. This helps when one file contains changes for two tasks: temporarily save the unfinished part, keep the remaining edits available for review, and restore the saved work later.

How do I save only part of a change?

  1. Open the working copy and review the current diff.
  2. Open Stash and choose Create Stash.
  3. Select the text files and hunks you want to set aside. Unversioned files and directories are selected as whole files.
  4. Give the stash a recognizable name.
  5. Choose Save and Remove from Working Copy, then inspect the remaining diff before committing anything.

Selected changes are removed after saving; unselected edits remain. This is local stashing, not a command to commit selected lines directly to the repository.

How do I restore the saved changes?

Return to the original working-copy path. Apply restores the stash and retains its record. Pop and Delete removes the record after successful application. Inspect the resulting diff. If application fails, inspect the working copy before retrying.

What can this flow save?

It supports selected text hunks and separately stored unversioned files. Conflicted versioned content, property-only changes and non-text versioned changes are outside this flow. Follow the actual preview rather than assuming every file can be stashed.

Are stashes shared with my team?

No. Stashes are stored locally by working-copy path, are not commits, and do not automatically follow a moved working copy. They are not interoperable with SVN's native shelves or a checkpoint history from another client.

Can I export a stash as a patch?

Copy or export includes only the text-patch portion. Separately stored unversioned file content is omitted, so a stash containing only unversioned files may have no exportable patch. Back up those files separately when transferring work. Deleting application data may erase local stashes; use commits or independent backups for important work.
